# Experiment audit — h1 (100% win rate)

**Command audited:** `uv run thesis-experiments h1 --max-train-seconds 240`
**Date/time:** 2026-08-31 ~20:10 BST
**Auditor:** experiment-auditor (claude-opus)
**git HEAD:** 1759b9b6

## Verdict

The 100% `win_rate` is **mis-measured, on top of a frictionless environment,
published from the wrong run** — three separate problems:

1. **`win_rate` is not a hit rate.** It is `mean(r > 0)` over a return series
   that has first been compounded from ~1,700–3,900 individual ticks into a
   single "bar" (`src/trading_rl/evaluation/metrics.py:423`, aggregation
   `metrics.py:42-82`). True per-tick hit rate on the TD3 test rollout is
   **57.0%** (247,133 up / 186,466 down / 535,619 flat). Compounding ~3,924
   ticks/bar amplifies per-bar SNR ~63×, so every bar's sign is deterministic
   and `win_rate` saturates at exactly 1.0 (positive drift) or 0.0 (negative
   drift — the non-DSR TD3 snapshot). Same artifact nulls `max_drawdown`,
   `gross_loss`, `downside_deviation`, `profit_factor`, `sortino_ratio`.
2. **The underlying edge is also an artifact.** `execution_price: mid` (spread
   never crossed), `trading_fees: 0.0`, zero latency, `average_holding_period`
   ~1.0 tick (PPO changes position on 839,104 / 839,106 steps). A free
   bid-ask-bounce harvester. Benchmark table on the same 224 bars: buy_and_hold
   -0.68% / 46% win rate vs "Strategy" +123.6% / 224-of-224 winning bars.
3. **The launched run never produced these numbers.** The run aborted during
   training (TD3 hit the 240s cap at 200k/3M steps; DDPG crashed on a deleted
   MLflow experiment; PPO and random never started). The exported snapshots are
   leftovers from 11–13 August log dirs, re-exported 2026-08-31 ~11:52Z.

## Minimum fix before re-running

1. Restore or permanently purge the deleted MLflow experiment
   `pooled_ddpg_hft_lob_state_space_pooled_streaming_selected_dsr` (blocks #5).
2. Drop `--max-train-seconds` (or set it high enough that training completes).
3. Make the env non-frictionless: real `trading_fees` and
   `execution_price: bid_ask`.
4. Replace the exported h1 TD3 snapshot with the `_dsr` scenario (#2).
5. Change `win_rate` to report the pre-aggregation hit rate, or rename it
   `pct_positive_bars` and state the bar size (#1). Route the per-bar vs
   annualised `sharpe_ratio` mismatch (#15) to `evaluation-metrics`.
6. Delete stale `thesis/qmd/results/pooled_*` snapshots so a failed run cannot
   silently serve month-old numbers (#6, #11).
